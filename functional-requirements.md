# Функциональные требования

| ID | Требование |
|---|---|
| FR-PM-001 | Merchant должен иметь возможность зарегистрировать токен платёжного метода для своего Customer. |
| FR-SUB-001 | Merchant должен иметь возможность создать MONTHLY-подписку с фиксированной суммой. |
| FR-SUB-002 | Merchant должен получать подписку и её статус по ID. |
| FR-SUB-003 | Merchant должен иметь возможность поставить ACTIVE-подписку на паузу. |
| FR-SUB-004 | Merchant должен иметь возможность возобновить PAUSED/PAST_DUE подписку. |
| FR-SUB-005 | Merchant должен иметь возможность отменить подписку. |
| FR-BIL-001 | Scheduler должен выбрать наступившие ACTIVE-подписки и создать плановый Payment. |
| FR-BIL-002 | Сервис должен создать Attempt и отправить запрос на списание в PSP. |
| FR-BIL-003 | Сервис должен обработать webhook PSP идемпотентно. |
| FR-BIL-004 | При временной ошибке сервис должен планировать retry согласно BR-SUB-008. |
| FR-BIL-005 | После успешного платежа сервис должен рассчитать следующий `next_charge_at`. |
| FR-PAY-001 | Merchant должен иметь возможность получить список платежей подписки. |
