# Допущения и решения

## AD-001. PSP абстрактный
Не используется API конкретного банка/эквайера. Это позволяет сосредоточиться на контракте интеграции и состояниях.

## AD-002. Token only
SubPay не является хранилищем карточных данных. Получение токена происходит на стороне PSP/его SDK, а SubPay получает только provider token.

## AD-003. Асинхронный источник истины
Ответ `PENDING` означает только принятие платежа. Финальный успех фиксируется после достоверного ответа/события PSP.

## AD-004. Exactly-once не обещается
В распределённой системе допускаются повторы сообщений. Проект строится на at-least-once доставке + идемпотентной обработке.

## AD-005. Retry не равен сетевому повтору
Новая бизнес-попытка оплаты создаёт новый Attempt. Повтор HTTP-запроса из-за timeout той же попытки использует тот же provider idempotency key и не считается новой Attempt.

## AD-006. Schedule упрощён
Только MONTHLY и фиксированная сумма. Usage billing и prorating оставлены за scope.
